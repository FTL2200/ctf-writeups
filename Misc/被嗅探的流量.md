### 3.2 阶段二：定位大包

**方法一：按 Length 列排序（图形界面）**

1. 在包列表点击 `Length` 列头，使其降序排列。
2. 观察结果：最大的包均为 **1514 字节**（以太网 MTU 上限），且 `Info` 列统一标注：

```text
[TCP PDU reassembled in 233]
```

**含义**：这些 1514 字节的包只是**分片**，完整消息被重组进 **233 号包**。

> 说明：Wireshark 中「重组后的包」其 `Length` 列显示的是单个网络帧长度，因此直接排序无法看到 164 KB 的数字，需依赖 `Info` 列的重组提示。

**方法二：按 HTTP 请求过滤（tshark）**

```powershell
& "C:\Program Files\Wireshark\tshark.exe" `
    -r "被嗅探的流量.pcapng" `
    -Y "http.request" `
    -T fields `
    -e frame.number -e ip.src -e ip.dst -e http.request.method -e http.request.uri
```

**输出（节选）**

```text
36   172.16.66.100 → 172.16.80.120   GET    /upload.php
54   172.16.66.100 → 172.16.80.120   POST   /upload.php
233  172.16.66.100 → 172.16.80.120   POST   /upload.php
310  172.16.66.100 → 172.16.80.5     GET    /sdk/vimService?wsdl
```

两次 `POST /upload.php` 即为文件上传请求。

**比对两者大小**：

```powershell
& "C:\Program Files\Wireshark\tshark.exe" -r "被嗅探的流量.pcapng" `
    -Y "http.request.method==POST" -T fields -e frame.number -e http.content_length
```

**输出**

```text
54    190
233   164161
```

| 包号 | Content-Length | 说明 |
| --- | --- | --- |
| 54 | 190 字节 | 空文件上传（`filename=""`） |
| **233** | **164161 字节** | **真实文件上传** |

### 3.4 阶段四：定位 Flag

**操作**

在 233 号包的十六进制区（Packet Bytes）查看数据尾部。

**观察到的结构**

```text
...JPEG 图像数据...
FF D9                                    ← JPEG 结束标记（EOI）
flag{da73d88936010da1eeeb36e945ec4b97}   ← ★ Flag
1A 0A                                    ← 换行符
------WebKitFormBoundaryIeRPZp2QAo2zkI2U ← multipart 表单边界
```

**十六进制对照（关键片段）**

```text
0110  ff d9 66 6c 61 67 7b 64 61 37 33 64 38 38 39   ..flag{da73d889
0120  36 30 31 30 64 61 31 65 65 65 62 33 36 65 39 34   36010da1eeeb36e94
0130  35 65 63 34 62 39 37 7d 1a 0a 0d 0a 2d 2d 2d 2d   5ec4b97}----
```

**分析结论**

Flag 被附加在 **JPEG 文件结束标记 `FF D9` 之后**、multipart 表单边界之前。

JPEG 解析器遇到 `FF D9` 即停止解析，因此额外数据不影响图片正常显示，仅通过十六进制查看才能发现——属于**文件尾部附加数据**手法。

## 五、知识点总结

### 5.1 协议分级中的「失衡判据」

| 现象 | 含义 | 后续动作 |
| --- | --- | --- |
| 包占比高、字节占比极低 | 大量小包 | 怀疑隐蔽信道（如每包 1 字节） |
| **包占比低、字节占比极高** | **少数大包** | **怀疑大文件传输** |
| 出现非常规协议 | 可能是自定义信道 | 查看该协议细节 |

### 5.2 TCP 分段与重组（Segmentation & Reassembly）

| 概念 | 说明 |
| --- | --- |
| MTU | 以太网默认 1500 字节，加上 14 字节帧头 = **1514 字节**为单帧上限 |
| 分段 | 超过 MTU 的数据被切分为多个 TCP 段传输 |
| 重组 | Wireshark 在内存中将分段拼回完整应用层数据，生成「重组包」 |
| 标识 | `Info` 列显示 `[TCP PDU reassembled in <包号>]` |

**本题中**：164 KB 的 JPEG 被切成 116 个 TCP 段，重组为 233 号包。

### 5.3 JPEG 文件结构

| 标记 | 含义 |
| --- | --- |
| `FF D8` | SOI（图像开始） |
| `FF E0` | APP0（JFIF 信息） |
| `FF E1` | APP1（EXIF 元数据，本题无） |
| `FF FE` | COM（注释，本题无） |
| `FF DB` | DQT（量化表） |
| `FF C0`/`FF C2` | SOF（帧头，含宽高） |
| `FF C4` | DHT（哈夫曼表） |
| `FF DA` | SOS（扫描数据开始） |
| **`FF D9`** | **EOI（图像结束）** |

**尾部附加数据检测**：`FF D9` 之后若仍存在数据，即为隐藏内容。

## 六、技术要点详解

### 6.1 为什么按 Length 排序看不到 164 KB

Wireshark 的 `Length` 列显示的是**单个网络帧的字节数**，受 MTU 限制最大 1514。

被重组的应用层数据（164 KB）并不作为单独一帧存在，因此不会出现在长度排序的顶部。

**正确判据**：观察 `Info` 列的 `[TCP PDU reassembled in N]`，它会直接指示完整数据的归属包号。

### 6.2 两种定位大包的策略对比

| 策略 | 操作 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 按 Length 排序 | 点击列头 | 快速、直观 | 分片会干扰判断 |
| 按 HTTP 方法过滤 | `-Y "http.request.method==POST"` | 直接定位上传动作 | 仅适用于 HTTP |
| 会话统计 | `-z conv,tcp` | 全局视角 | 需二次定位 |
| 协议分级 | `-z io,phs` | 无先验知识时可用 | 只能给出方向 |

**本题推荐组合**：协议分级（发现异常）→ HTTP 过滤（定位请求）→ 比对 Content-Length（确定目标）。

### 6.3 干扰项的识别

| 流量类型 | 特征 | 是否相关 |
| --- | --- | --- |
| SSDP `M-SEARCH` | 发往 `239.255.255.250:1900` | 无关（内网设备发现） |
| DNS 反向查询 | `in-addr.arpa` / `ip6.arpa` | 无关（正常解析） |
| TLS 至微软 IP | `137.135.12.16:443` | 无关（系统更新类流量） |
| `GET /sdk/vimService?wsdl` | VMware vCenter SDK | 可能为环境噪声 |
| **`POST /upload.php`** | **携带 164 KB multipart 数据** | **★ 本题目标** |

## 八、同类题型扩展

### 8.1 流量题常见考点

| 题型 | 识别方法 | 提取手段 |
| --- | --- | --- |
| **HTTP 文件上传/下载** | `POST` + 大 `Content-Length` | 重组包 + 提取载荷 |
| TCP 隐蔽信道 | 每包极小载荷 | `-Y "tcp.len==1"` |
| DNS 隧道 | 超长域名 | `-e dns.qry.name` |
| ICMP 隧道 | 异常 ICMP 载荷 | `-e icmp.data` |
| USB 键盘流量 | `usb.capdata` | 键码还原 |
| 加密流量 | TLS 握手 | 导入密钥解密 |

### 8.2 流量题通用流程

```text
① 协议分级 → 找失衡
        ↓
② 定位可疑会话（会话统计 / 方法过滤）
        ↓
③ 跳转目标包，查看重组信息
        ↓
④ 提取载荷（导出对象 / 重组数据 / 追踪流）
        ↓
⑤ 还原文件，分析结构（文件头尾、尾部附加数据）
        ↓
⑥ 重复：文件里可能还有下一层
```

### 8.3 常用 tshark 命令

```powershell
# 全局协议统计
tshark -r x.pcapng -z io,phs

# TCP 会话统计
tshark -r x.pcapng -z conv,tcp

# 列出所有 HTTP 请求
tshark -r x.pcapng -Y "http.request" -T fields -e frame.number -e http.request.method -e http.request.uri

# 查看 POST 请求大小
tshark -r x.pcapng -Y "http.request.method==POST" -T fields -e frame.number -e http.content_length

# 追踪 TCP 流
tshark -r x.pcapng -z follow,tcp,raw,2

# 提取某流全部载荷
tshark -r x.pcapng -Y "tcp.stream==2 && tcp.len>0" -T fields -e tcp.payload
```
